# 给 midea-local 的可视化只读诊断提案

## 背景与仓库现状

`midea-local` 的定位是 Midea M-Smart 设备的局域网 Python 库，并提供 CLI 供发现、读取和控制设备。当前公开仓库的顶层结构包含 Python 包、Lua 协议参考、测试和脚本；README 展示 Python API 与 CLI 用法。我在截至 2026-10-25 检查的 `main` 分支文件列表及 README 中没有找到内置网页仪表盘或可视化实时状态监测界面。这个结论只针对已检查的公开仓库内容，不代表社区没有独立工具。

## 建议

考虑将一个独立、可选的只读诊断示例放在仓库之外，或在文档增加链接，供用户观察设备实际回报的状态。首个验证目标可以是 DA 类波轮洗衣机：将库现有的异步发现/API 与状态属性用于本地网页，展示原始状态值、采样时间、错误码和水位设定码趋势，并导出本地 CSV/JSONL。

诊断界面应明确标注“只读”，默认只绑定 `127.0.0.1`，不提供启动、暂停、设置、复位或固件写入接口；不上传数据、不请求云端凭据。采样频率受设备响应时延限制，目标 1 秒不保证真实每秒更新。显示的 `wash_level` 是控制器回报的设定码，不是传感器原始值或实际水量。字段应按具体设备能力显示，缺失属性不可填造。

## 现有原型

独立原型和匿名案例材料见本发布包的 `README.md`、`CASE_STUDY_ZH.md` 与 Python 脚本。它依赖已发布的 `midea-local` 包，不复制上游实现代码；上游 MIT 项目及版权信息见 `ATTRIBUTION.md`。原型已做语法检查和 CLI 帮助验证，但目前仅在一台 DA V2 洗衣机上进行过有限验证，尚不足以承诺支持其他型号、设备类别或固件。

## 希望维护者反馈

1. 这种面向现场排障的只读 UI 是否符合项目范围？
2. 如果有兴趣，维护者更希望接收独立工具链接、文档示例，还是可选的诊断额外组件？
3. 对设备属性读取、采样节奏、日志脱敏或 API 使用方式，是否有维护者偏好的约定？

我建议先通过 Discussions 的 Ideas 或 Show and tell 分类讨论范围与放置位置，再根据反馈整理小型 PR。若维护者认为可视化工具不属于核心库，原型可继续作为独立仓库维护并在讨论中提供链接。

## 证据与限制

- 用户报告：上部盖板拆下后面板乱跳现象暂时消失；尚无安全复装后的受控 A/B 测试，不能据此确认因果或具体损坏零件。
- 局域网样本支持读取若干 DA 状态字段，但没有捕获异常首次洗涤的同步连续数据；样本不足以证明界面能够判定触控板、电极弹簧、排线、主控、水位传感器或电机故障。
- 发布案例应继续匿名化，不附设备身份、家庭网络地址、原始发现结果或未脱敏日志。
